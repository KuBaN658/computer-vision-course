# DEtection TRansformer (DETR)
## Обзор архитектуры
DETR в основном используют для задач детекции объектов — процесса детекции объектов на изображении. Например, входом модели было бы изображение дороги, а выходом модели могло бы быть `[('car',X1,Y1,W1,H1),('pedestrian',X2,Y2,W2,H2)]`, где X, Y, W, H представляют координаты x, y, обозначающие положение ограничивающего прямоугольника, а также ширину и высоту прямоугольника. 
Традиционная модель детекции объектов вроде YOLO состоит из вручную спроектированных признаков вроде априорных якорных прямоугольников, которые требуют начальных догадок о положениях и формах объектов, влияя на последующее обучение. Затем используют шаги постобработки, чтобы удалить перекрывающиеся ограничивающие прямоугольники, что требует тщательного выбора эвристик фильтрации. 
DEtection TRansformer, сокращённо DETR, упрощает детектор, используя трансформер энкодер-декодер после backbone извлечения признаков, чтобы напрямую предсказывать ограничивающие прямоугольники параллельно, требуя минимальной постобработки.

![Схема архитектуры DETR](https://huggingface.co/datasets/hf-vision/course-assets/resolve/main/DETR.png)
Архитектура модели DETR начинается с CNN-backbone, подобно другим сетям на основе изображений; его выход обрабатывается и подаётся в энкодер трансформера, давая N эмбеддингов. Эмбеддинги энкодера складываются с обучаемыми позиционными эмбеддингами (называемыми object queries) и используются в декодере трансформера, генерируя ещё N эмбеддингов. На финальном шаге каждый из N эмбеддингов пропускается через отдельные слои прямого распространения, чтобы предсказать ширину, высоту, координаты ограничивающего прямоугольника, а также класс объекта (или то, есть ли объект).

## Ключевые особенности

### Энкодер-декодер
Как и у других трансформеров, энкодер трансформера ожидает, что выход CNN-backbone будет последовательностью. Поэтому карта признаков размера `[dimension, height, width]` уменьшается, а затем уплощается до `[dimension, less than height x width]`.
![Карты признаков энкодера](https://huggingface.co/datasets/hf-vision/course-assets/resolve/main/DETR_FeatureMaps.png)
_**Слева**: визуализированы 12 из 256 измерений карт признаков. Каждое измерение извлекает некоторые признаки исходного изображения кошки, уменьшая исходное изображение. Некоторые измерения сильнее фокусируются на узорах на кошке; некоторые сильнее фокусируются на простынях._ 
_**Справа**: сохраняя исходную размерность признаков 256, ширина и высота дополнительно уменьшаются и уплощаются до размера 850._  
Поскольку трансформеры инвариантны к перестановкам, позиционные эмбеддинги добавляются и к энкодеру, и к декодеру, чтобы напомнить модели, откуда на изображении пришли эмбеддинги. В энкодере используют фиксированное позиционное кодирование, а в декодере — обучаемое позиционное кодирование (object queries). Фиксированные кодировки похожи на те, что использовались в оригинальной статье о Transformer: кодировки задаются синусоидальными функциями разных частот на разных измерениях признаков. Это даёт ощущение позиции без каких-либо обучаемых параметров, индексируемых по положению на изображении. Обучаемые кодировки также индексируются по положениям, но у каждой позиции своя кодировка, которая обучается на протяжении обучения, чтобы обозначать положения так, как модель это понимает.

### Глобальная функция потерь на основе множеств
В YOLO, популярной модели детекции объектов, функция потерь состоит из потери по ограничивающему прямоугольнику, objectness (то есть вероятности существования объекта в области интереса) и классовой потери. Потеря считается по нескольким ограничивающим прямоугольникам на каждую ячейку сетки — это фиксированное число. С другой стороны, в DETR архитектура должна генерировать уникальные ограничивающие прямоугольники инвариантно к перестановкам (то есть порядок детекций не важен в выходе, а ограничивающие прямоугольники должны различаться и не могут все быть одинаковыми). Поэтому требуется сопоставление, чтобы оценить, насколько хороши предсказания.

**Двудольное сопоставление**   
Двудольное сопоставление (bipartite matching) — способ вычислить взаимно однозначное сопоставление между истинными ограничивающими прямоугольниками и предсказанными прямоугольниками. Оно находит соответствия с наивысшим сходством между истинными и предсказанными ограничивающими прямоугольниками, а также классами. Это гарантирует, что ближайшее предсказание будет сопоставлено с соответствующей истинной разметкой, чтобы правильно скорректировать прямоугольники и классы в функции потерь. Если сопоставление не делать, предсказания, не выровненные с порядком истинной разметки, были бы помечены как неверные, даже если они верны.

## Эволюция DETR
### Deformable DETR
Две главные проблемы DETR — долгий и медленный процесс сходимости и неоптимальная детекция мелких объектов. 
**Деформируемое внимание**   
Первая проблема решается с помощью деформируемого внимания (deformable attention), которое сокращает число точек сэмплирования, которым нужно уделять внимание. Традиционное внимание неэффективно из-за глобального внимания и сильно ограничивает разрешение, которое может иметь изображение. Модель уделяет внимание только фиксированному числу точек сэмплирования вокруг каждой опорной точки, а опорные точки обучаются моделью на основе входа. Например, на изображении собаки опорная точка может быть в центре собаки, а точки сэмплирования — около ушей, пасти, хвоста и т. д.

**Модуль многомасштабного деформируемого внимания**   
Вторая проблема решается подобно YOLOv3: вводятся многомасштабные карты признаков. В свёрточных нейронных сетях более ранние слои извлекают более мелкие детали (например, линии), а более поздние слои — более крупные детали (например, колёса, уши). Аналогично разные слои деформируемого внимания дают разные уровни разрешения. Соединяя выходы некоторых из этих слоёв энкодера с декодером, модель может детектировать объекты множества размеров.

### Conditional DETR
Conditional DETR также ставит целью решить проблему медленной сходимости обучения в исходном DETR, давая сходимость более чем в 6,7 раза быстрее. Авторы обнаружили, что object queries общие и не специфичны для входного изображения. Используя **условное перекрёстное внимание (Conditional Cross-Attention)** в декодере, запросы могут лучше локализовать области для регрессии ограничивающего прямоугольника.
![Слой декодера для Conditional DETR](https://huggingface.co/datasets/hf-vision/course-assets/resolve/main/DETR_DecoderLayer.png)
_Слева: слой декодера DETR. Справа: слой декодера Conditional DETR_   
Исходные слои декодера DETR и Conditional DETR сравниваются на рисунке выше; главное различие — вход запроса блока перекрёстного внимания. Авторы проводят различие между контентным запросом c<sub>q</sub> (выход самовнимания декодера) и пространственным запросом p<sub>q</sub>. Исходный DETR просто складывает их. В Conditional DETR их конкатенируют: c<sub>q</sub> фокусируется на содержимом объекта, а p<sub>q</sub> — на областях ограничивающего прямоугольника.   
Пространственный запрос p<sub>q</sub> — результат проекции эмбеддингов декодера и object queries в одно и то же пространство (становятся T и p<sub>s</sub> соответственно) и их перемножения. Эмбеддинги декодера предыдущих слоёв содержат информацию об областях ограничивающего прямоугольника, а object queries содержат информацию об обученных опорных точках для каждого ограничивающего прямоугольника. Поэтому их проекции объединяются в представление, которое позволяет перекрёстному вниманию измерять их сходство со входом энкодера и синусоидальным позиционным эмбеддингом. Это эффективнее, чем DETR, который использует только object queries и фиксированные опорные точки.

## Инференс DETR

Вы можете выполнять инференс с существующими моделями DETR на Hugging Face Hub следующим образом:

```python
from transformers import DetrImageProcessor, DetrForObjectDetection
import torch
from PIL import Image
import requests

url = "http://images.cocodataset.org/val2017/000000039769.jpg"
image = Image.open(requests.get(url, stream=True).raw)

# initialize the model
processor = DetrImageProcessor.from_pretrained(
    "facebook/detr-resnet-101", revision="no_timm"
)
model = DetrForObjectDetection.from_pretrained(
    "facebook/detr-resnet-101", revision="no_timm"
)

# preprocess the inputs and infer
inputs = processor(images=image, return_tensors="pt")
outputs = model(**inputs)

# convert outputs (bounding boxes and class logits) to COCO API
# non max supression above 0.9
target_sizes = torch.tensor([image.size[::-1]])
results = processor.post_process_object_detection(
    outputs, target_sizes=target_sizes, threshold=0.9
)[0]

for score, label, box in zip(results["scores"], results["labels"], results["boxes"]):
    box = [round(i, 2) for i in box.tolist()]
    print(
        f"Detected {model.config.id2label[label.item()]} with confidence "
        f"{round(score.item(), 3)} at location {box}"
    )
```

Выходы ниже.

```bash

Detected remote with confidence 0.997 at location [328.13, 75.93, 372.81, 187.66]
Detected remote with confidence 0.997 at location [39.34, 70.13, 175.56, 118.78]
Detected cat with confidence 0.998 at location [15.36, 51.75, 316.89, 471.16]

```

## Реализация DETR на PyTorch
Реализация DETR из оригинальной статьи показана ниже:
```python
import torch
from torch import nn
from torchvision.models import resnet50


class DETR(nn.Module):
    def __init__(
        self, num_classes, hidden_dim, nheads, num_encoder_layers, num_decoder_layers
    ):
        super().__init__()
        self.backbone = nn.Sequential(*list(resnet50(pretrained=True).children())[:-2])
        self.conv = nn.Conv2d(2048, hidden_dim, 1)
        self.transformer = nn.Transformer(
            hidden_dim, nheads, num_encoder_layers, num_decoder_layers
        )
        self.linear_class = nn.Linear(hidden_dim, num_classes + 1)
        self.linear_bbox = nn.Linear(hidden_dim, 4)
        self.query_pos = nn.Parameter(torch.rand(100, hidden_dim))
        self.row_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))
        self.col_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))

    def forward(self, inputs):
        x = self.backbone(inputs)
        h = self.conv(x)
        H, W = h.shape[-2:]
        pos = (
            torch.cat(
                [
                    self.col_embed[:W].unsqueeze(0).repeat(H, 1, 1),
                    self.row_embed[:H].unsqueeze(1).repeat(1, W, 1),
                ],
                dim=-1,
            )
            .flatten(0, 1)
            .unsqueeze(1)
        )
        h = self.transformer(
            pos + h.flatten(2).permute(2, 0, 1), self.query_pos.unsqueeze(1)
        )
        return self.linear_class(h), self.linear_bbox(h).sigmoid()
```
### Разбор функции `forward` построчно: 
**Backbone**   
Входное изображение сначала пропускается через backbone ResNet, а затем через свёрточный слой, который снижает размерность до `hidden_dim`.
```python
x = self.backbone(inputs)
h = self.conv(x)
```
Они объявлены в функции `__init__`.
```python
self.backbone = nn.Sequential(*list(resnet50(pretrained=True).children())[:-2])
self.conv = nn.Conv2d(2048, hidden_dim, 1)
```

**Позиционные эмбеддинги**

Хотя в статье в энкодере и декодере используют фиксированные и обучаемые эмбеддинги соответственно, авторы в реализации для простоты использовали обучаемые эмбеддинги для обоих.    
```python
pos = (
    torch.cat(
        [
            self.col_embed[:W].unsqueeze(0).repeat(H, 1, 1),
            self.row_embed[:H].unsqueeze(1).repeat(1, W, 1),
        ],
        dim=-1,
    )
    .flatten(0, 1)
    .unsqueeze(1)
)
```
Они объявлены здесь как `nn.Parameter`. Эмбеддинги строк и столбцов вместе обозначают положения на изображении.
```python
self.row_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))
self.col_embed = nn.Parameter(torch.rand(50, hidden_dim // 2))
```
**Изменение размера**   
Перед попаданием в трансформер признаки размера `(batch size, hidden_dim, H, W)` переформируются в `(hidden_dim, batch size, H*W)`. Это делает их последовательным входом для трансформера.
```python
h.flatten(2).permute(2, 0, 1)
```
**Трансформер**   
Функция `nn.Transformer` принимает первый параметр как вход энкодера, а второй параметр — как вход энкодера. Как видно, энкодер принимает изменённые в размере признаки, сложенные с позиционными эмбеддингами, а декодер принимает `query_pos` — позиционный эмбеддинг декодера.
```python
h = self.transformer(pos + h.flatten(2).permute(2, 0, 1), self.query_pos.unsqueeze(1))
```
**Сеть прямого распространения**   
В конце выходы — тензор размера `(query_pos_dim, batch size, hidden_dim)` — пропускаются через два линейных слоя. 
```python
return self.linear_class(h), self.linear_bbox(h).sigmoid()
```
Первый из них предсказывает класс. Дополнительный класс добавляется для класса `No Object`.
```python
self.linear_class = nn.Linear(hidden_dim, num_classes + 1)
```
Второй линейный слой предсказывает ограничивающий прямоугольник с выходным размером 4 для координат xy, высоты и ширины.
```python
self.linear_bbox = nn.Linear(hidden_dim, 4)
```
