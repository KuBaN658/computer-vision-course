# MobileNet

MobileNet — тип архитектуры нейронной сети, разработанный для мобильных устройств. Её создала исследовательская команда Google, впервые представив в 2017 году. Главная цель MobileNet — обеспечить высококачественную классификацию изображений и детекцию объектов с низкой задержкой на смартфонах, планшетах и других устройствах с ограниченными ресурсами.

MobileNet достигает этого за счёт послойно-разделимых свёрток, которые являются более эффективной альтернативой обычным свёрткам. Послойно-разделимые свёртки разбивают вычисление на два отдельных шага: depthwise-свёртку, за которой следует pointwise-свёртка. Это даёт существенное сокращение параметров и вычислительной сложности, позволяя MobileNet эффективно работать на мобильных устройствах.

## Типы свёрток в MobileNet

Заменяя обычные свёрточные слои этими послойно-разделимыми свёртками и pointwise-свёртками, MobileNet достигает высокой точности при минимальных вычислительных затратах, что делает её хорошо подходящей для мобильных устройств и других платформ с ограниченными ресурсами. В MobileNet используют два типа свёрток:

### Послойно-разделимые свёртки (depthwise separable convolutions)

В традиционных свёрточных слоях каждый фильтр применяет свои веса сразу ко всем входным каналам. Послойно-разделимые свёртки разбивают это на два шага: depthwise-свёртку, за которой следует pointwise-свёртка.

На этом шаге свёртка выполняется отдельно для каждого канала (одного цвета или признака) во входном изображении с помощью небольшого фильтра (обычно 3x3). Выход этого шага того же размера, что и вход, но с меньшим числом каналов.

### Поэлементные свёртки (pointwise convolutions)

Этот тип свёртки применяет один фильтр (обычно 1x1) ко всем каналам и во входном, и в выходном слоях. У него меньше параметров, чем у обычной свёртки, и его можно рассматривать как альтернативу полносвязным слоям, что делает его подходящим для мобильных устройств с ограниченными вычислительными ресурсами.

После depthwise-свёртки этот шаг объединяет отфильтрованные выходы предыдущих шагов с помощью ещё одного свёрточного слоя 1x1. Эта операция эффективно агрегирует признаки, выученные depthwise-свёртками, в меньший набор признаков, снижая общую сложность и сохраняя важную информацию.

### Почему мы используем эти свёртки вместо обычных?
Чтобы лучше понять, упростим и объясним:

#### Обычные свёртки: большой универсальный фильтр

Представьте большой толстый фильтр (как губка со многими слоями). Этот фильтр накладывают на всё изображение. Он обрабатывает все части изображения и все его признаки (например, цвета) сразу. Для этого нужно много работы (вычислений) и большой фильтр (память).

#### Послойно-разделимые свёртки — двухшаговый, более лёгкий процесс:
MobileNet делает этот процесс проще. Большой фильтр разбивается на два меньших, более простых шага:

 - **Шаг 1 — Depthwise-свёртка:** Сначала используется тонкий фильтр (как один слой губки) для каждого признака изображения
   отдельно (как обработка каждого цвета по отдельности). Это меньше работы, потому что каждый фильтр маленький и простой.
   
 - **Шаг 2 — Pointwise-свёртка:** Затем используется ещё один маленький фильтр (просто крошечная точка), чтобы смешать эти признаки обратно вместе. Этот шаг похож на краткое резюме того, что нашли первые фильтры.

#### О чём эти шаги?

MobileNet использует эти два меньших шага вместо одного большого: это как более лёгкая версия работы, нужной в обычных свёртках. Это эффективнее, особенно на устройствах, которые не очень мощные, например смартфонах.

С меньшими фильтрами MobileNet не нужна такая большая память. Это как меньшая коробка для всех инструментов: её проще уместить в меньшие устройства.

### Как работают свёртки 1x1 по сравнению с обычными свёртками?

#### Обычные свёртки

-   Обычные свёртки используют большее ядро (например, 3x3 или 5x5), чтобы сразу смотреть на группу пикселей изображения. Это как наблюдать небольшой фрагмент картинки, чтобы понять часть сцены.
-   Такие свёртки хорошо понимают признаки вроде границ, углов и текстур, анализируя, как пиксели расположены рядом друг с другом.

#### Свёртки 1x1

-  Свёртка 1x1 смотрит на один пиксель за раз. Она не пытается понять расположение соседних пикселей.
-  Хотя она смотрит на один пиксель, она учитывает всю информацию из разных каналов (например, каналов RGB в цветном изображении). Она комбинирует эти каналы, чтобы создать новую версию этого пикселя.
-  Свёртка 1x1 может увеличивать или уменьшать число каналов. Это значит, что она может упрощать информацию (уменьшая каналы) или создавать более сложную информацию (увеличивая каналы).

#### Ключевые различия

-   **Область фокуса:** Обычные свёртки анализируют набор пикселей вместе, чтобы понимать паттерны, тогда как свёртки 1x1 сосредоточены на отдельных пикселях, комбинируя информацию из разных каналов.
-   **Назначение:** Обычные свёртки используют для детекции паттернов и признаков на изображении. Свёртки 1x1 же в основном используют, чтобы менять глубину каналов, помогая подстраивать сложность информации для последующих слоёв нейронной сети ради эффективности на слабых устройствах.

MobileNet также применяет техники вроде channel-wise linear bottleneck layers, которые повышают точность модели при сокращении числа параметров. Архитектура спроектирована с оптимизациями под разные аппаратные платформы, включая CPU, GPU и даже специализированное железо вроде Tensor Processing Units (TPU) от Google.

### Поканальные линейные bottleneck-слои
Поканальные линейные bottleneck-слои помогают ещё сильнее сократить число параметров и вычислительную стоимость, сохраняя высокую точность в задачах классификации изображений.

Поканальный линейный bottleneck-слой состоит из трёх основных операций, применяемых последовательно:
1. **Depthwise-свёртка:** На этом шаге свёртка выполняется отдельно для каждого канала (одного цвета или признака) во входном изображении с помощью небольшого фильтра (обычно 3x3). Выход этого шага того же размера, что и вход, но с меньшим числом каналов.
2. **Пакетная нормализация (batch normalization):** Эта операция нормализует значения активаций по каждому каналу, помогая стабилизировать процесс обучения и улучшить обобщающую способность.
3. **Функция активации:** Обычно после пакетной нормализации используют активацию ReLU (Rectified Linear Unit), чтобы внести нелинейность в сеть.

### Что делает ReLU?

Во время обучения могут возникать некоторые проблемы. Сначала объясним их, затем объясним, что ReLU делает с этими проблемами.

#### Проблема затухания градиента

В глубоких нейронных сетях, особенно при обратном распространении, может возникать проблема затухания градиента. Это происходит, когда градиенты (которые используют для обновления весов сети) становятся очень маленькими по мере передачи назад через слои сети. Если эти градиенты становятся слишком маленькими, они «затухают», и сети трудно эффективно учиться и корректировать веса.

У ReLU линейная, ненасыщающаяся форма для положительных значений (где она просто выдаёт вход, если он положительный), поэтому градиенты не становятся слишком маленькими, что позволяет быстрее учиться и эффективнее корректировать веса в сети.

#### Нелинейность

Без нелинейности нейронная сеть, сколько бы слоёв у неё ни было, работала бы как линейная модель, неспособная выучивать сложные паттерны.

Нелинейные функции вроде ReLU позволяют нейронным сетям захватывать и выучивать сложные зависимости в данных.

### Вывод (inference)

Вы можете использовать Hugging Face transformers, чтобы делать вывод с вариациями моделей transformers, как ниже:

```python
from transformers import AutoImageProcessor, AutoModelForImageClassification
from PIL import Image
import requests

url = "http://images.cocodataset.org/val2017/000000039769.jpg"
image = Image.open(requests.get(url, stream=True).raw)

# initialize processor and model
preprocessor = AutoImageProcessor.from_pretrained("google/mobilenet_v2_1.0_224")
model = AutoModelForImageClassification.from_pretrained("google/mobilenet_v2_1.0_224")

# preprocess the inputs
inputs = preprocessor(images=image, return_tensors="pt")

# get the output and the class labels
outputs = model(**inputs)
logits = outputs.logits

predicted_class_idx = logits.argmax(-1).item()
print("Predicted class:", model.config.id2label[predicted_class_idx])
```

```
Predicted class: tabby, tabby cat
```

### Пример реализации на PyTorch

Ниже вы найдёте пример реализации MobileNet на PyTorch:

```python  
import torch
import torch.nn as nn
import torch.nn.functional as F


class DepthwiseSeparableConv(nn.Module):
    def __init__(self, in_channels, out_channels, stride):
        super().__init__()
        self.depthwise = nn.Conv2d(
            in_channels,
            in_channels,
            kernel_size=3,
            stride=stride,
            padding=1,
            groups=in_channels,
        )
        self.pointwise = nn.Conv2d(
            in_channels, out_channels, kernel_size=1, stride=1, padding=0
        )

    def forward(self, x):
        x = self.depthwise(x)
        x = self.pointwise(x)
        return x


class MobileNet(nn.Module):
    def __init__(self, num_classes=1000):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 32, kernel_size=3, stride=2, padding=1)

        # MobileNet body
        self.dw_conv2 = DepthwiseSeparableConv(32, 64, 1)
        self.dw_conv3 = DepthwiseSeparableConv(64, 128, 2)
        self.dw_conv4 = DepthwiseSeparableConv(128, 128, 1)
        self.dw_conv5 = DepthwiseSeparableConv(128, 256, 2)
        self.dw_conv6 = DepthwiseSeparableConv(256, 256, 1)
        self.dw_conv7 = DepthwiseSeparableConv(256, 512, 2)

        # 5 depthwise separable convolutions with stride 1
        self.dw_conv8 = DepthwiseSeparableConv(512, 512, 1)
        self.dw_conv9 = DepthwiseSeparableConv(512, 512, 1)
        self.dw_conv10 = DepthwiseSeparableConv(512, 512, 1)
        self.dw_conv11 = DepthwiseSeparableConv(512, 512, 1)
        self.dw_conv12 = DepthwiseSeparableConv(512, 512, 1)

        self.dw_conv13 = DepthwiseSeparableConv(512, 1024, 2)
        self.dw_conv14 = DepthwiseSeparableConv(1024, 1024, 1)

        self.avg_pool = nn.AdaptiveAvgPool2d(1)
        self.fc = nn.Linear(1024, num_classes)

    def forward(self, x):
        x = self.conv1(x)
        x = F.relu(x)

        x = self.dw_conv2(x)
        x = F.relu(x)
        x = self.dw_conv3(x)
        x = F.relu(x)
        x = self.dw_conv4(x)
        x = F.relu(x)
        x = self.dw_conv5(x)
        x = F.relu(x)
        x = self.dw_conv6(x)
        x = F.relu(x)
        x = self.dw_conv7(x)
        x = F.relu(x)

        x = self.dw_conv8(x)
        x = F.relu(x)
        x = self.dw_conv9(x)
        x = F.relu(x)
        x = self.dw_conv10(x)
        x = F.relu(x)
        x = self.dw_conv11(x)
        x = F.relu(x)
        x = self.dw_conv12(x)
        x = F.relu(x)

        x = self.dw_conv13(x)
        x = F.relu(x)
        x = self.dw_conv14(x)
        x = F.relu(x)

        x = self.avg_pool(x)
        x = x.view(x.size(0), -1)
        x = self.fc(x)

        return x


# Create the model
mobilenet = MobileNet(num_classes=1000)
print(mobilenet)
```

Предобученный чекпоинт модели MobileNet также можно найти по этой [ссылке](https://huggingface.co/google/mobilenet_v2_1.0_224) на Hugging Face.
