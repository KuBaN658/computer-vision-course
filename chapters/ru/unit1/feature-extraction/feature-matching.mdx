# Сопоставление признаков

Как сопоставить детектированные признаки с одного изображения на другое? Сопоставление признаков включает сравнение ключевых атрибутов на разных изображениях, чтобы найти сходства. Сопоставление признаков полезно во многих применениях компьютерного зрения, включая понимание сцен, сшивку изображений, трекинг объектов и распознавание образов.

## Полный перебор (brute-force search)

Представьте, что у вас огромная коробка пазлов, и вы пытаетесь найти конкретный кусочек, который подходит к вашей картинке. Это похоже на поиск совпадающих признаков на изображениях. Вместо какой-то особой стратегии вы решаете проверять каждый кусочек один за другим, пока не найдёте нужный. Этот прямолинейный метод — полный перебор. Преимущество полного перебора — простота. Вам не нужны особые трюки — только терпение. Однако это может занимать много времени, особенно если кусочков очень много. В контексте сопоставления признаков этот подход полного перебора сродни сравнению каждого пикселя на одном изображении с каждым пикселем на другом, чтобы увидеть, совпадают ли они. Это исчерпывающе, и это может занять много времени, особенно для больших изображений.

Теперь, когда у нас есть интуитивное представление о том, как находят совпадения полным перебором, давайте погрузимся в алгоритмы. Мы будем использовать дескрипторы, о которых узнали в предыдущей главе, чтобы найти совпадающие признаки на двух изображениях.

import cv2

**Полный перебор с SIFT**

Начнём с инициализации детектора SIFT.

```python
sift = cv2.SIFT_create()
```

Найдите ключевые точки и дескрипторы с помощью SIFT.

```python
kp1, des1 = sift.detectAndCompute(img1, None)
kp2, des2 = sift.detectAndCompute(img2, None)
```

Найдите совпадения с помощью k ближайших соседей.

```python
bf = cv2.BFMatcher()
matches = bf.knnMatch(des1, des2, k=2)
```

Примените тест отношения, чтобы отфильтровать лучшие совпадения.

```python
good = []
for m, n in matches:
    if m.distance < 0.75 * n.distance:
        good.append([m])
```

Нарисуйте совпадения.

```python
img3 = cv2.drawMatchesKnn(
    img1, kp1, img2, kp2, good, None, flags=cv2.DrawMatchesFlags_NOT_DRAW_SINGLE_POINTS
)
```

**Полный перебор с бинарными дескрипторами ORB**

Инициализируйте дескриптор ORB.

```python
orb = cv2.ORB_create()
```

Найдите ключевые точки и дескрипторы.

```python
kp1, des1 = orb.detectAndCompute(img1, None)
kp2, des2 = orb.detectAndCompute(img2, None)
```

Поскольку ORB — бинарный дескриптор, мы находим совпадения, используя [расстояние Хэмминга](https://www.geeksforgeeks.org/hamming-distance-two-strings/),
которое измеряет различие между двумя строками одинаковой длины.

```python
bf = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=True)
```

Теперь найдём совпадения.

```python
matches = bf.match(des1, des2)
```

Мы можем отсортировать их в порядке расстояния следующим образом.

```python
matches = sorted(matches, key=lambda x: x.distance)
```

Нарисуйте первые n совпадений.

```python
img3 = cv2.drawMatches(
    img1,
    kp1,
    img2,
    kp2,
    matches[:n],
    None,
    flags=cv2.DrawMatchesFlags_NOT_DRAW_SINGLE_POINTS,
)
```

**Fast Library for Approximate Nearest Neighbors (FLANN)**

FLANN был предложен в [Fast Approximate Nearest Neighbors With Automatic Algorithm Configuration](https://www.cs.ubc.ca/research/flann/uploads/FLANN/flann_visapp09.pdf) авторами Muja и Lowe. Чтобы объяснить FLANN, продолжим пример с пазлом. Представьте огромный пазл с сотнями разбросанных кусочков. Ваша цель — организовать эти кусочки по тому, насколько хорошо они подходят друг к другу. Вместо того чтобы случайно пытаться сопоставить кусочки,
FLANN использует несколько хитрых приёмов, чтобы быстро понять, какие кусочки с наибольшей вероятностью идут вместе. Вместо того чтобы пробовать каждый кусочек против каждого другого, FLANN упрощает процесс, находя кусочки, которые приблизительно похожи. Это значит, что он может делать обоснованные догадки о том, какие кусочки могут хорошо подойти друг к другу, даже если это не точное совпадение. Под капотом FLANN использует так называемые k-D деревья. Представьте это как особый способ организации кусочков пазла. Вместо того чтобы проверять каждый кусочек против каждого другого, FLANN расставляет их в древовидную структуру, которая ускоряет поиск совпадений. В каждом узле k-D дерева FLANN кладёт вместе кусочки с похожими признаками. Это как сортировать кусочки пазла с похожими формами или цветами по кучкам. Так, когда вы ищете совпадение, вы можете быстро проверить кучку, в которой с наибольшей вероятностью похожие кусочки. Допустим, вы ищете кусочек «неба». Вместо того чтобы перебирать все кусочки, FLANN ведёт вас в нужное место k-D дерева, где отсортированы кусочки цвета неба. FLANN также подстраивает стратегию на основе признаков кусочков пазла. Если пазл с множеством цветов, он сосредоточится на цветовых признаках. И наоборот, если это пазл со сложными формами, он обратит внимание на эти формы. Балансируя скорость и точность при поиске совпадающих признаков, FLANN существенно улучшает время запроса.

Сначала мы создаём словарь, чтобы указать алгоритм, который будем использовать; для SIFT или SURF он выглядит следующим образом.

```python
FLANN_INDEX_KDTREE = 1
index_params = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)
```

Для ORB используем параметры из статьи.

```python
FLANN_INDEX_LSH = 6
index_params = dict(
    algorithm=FLANN_INDEX_LSH, table_number=12, key_size=20, multi_probe_level=2
)
```

Мы также создаём словарь, чтобы указать максимальное число листьев для посещения, следующим образом.

```python
search_params = dict(checks=50)
```

Инициализируйте детектор SIFT.

```python
sift = cv2.SIFT_create()
```

Найдите ключевые точки и дескрипторы с помощью SIFT.

```python
kp1, des1 = sift.detectAndCompute(img1, None)
kp2, des2 = sift.detectAndCompute(img2, None)
```

Теперь определим параметры FLANN. Здесь trees — это число бинов, которое вы хотите.

```python
FLANN_INDEX_KDTREE = 1
index_params = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)
search_params = dict(checks=50)
flann = cv2.FlannBasedMatcher(index_params, search_params)

matches = flann.knnMatch(des1, des2, k=2)
```

Мы будем рисовать только хорошие совпадения, поэтому создадим маску.

```python
matchesMask = [[0, 0] for i in range(len(matches))]
```

Мы можем выполнить тест отношения, чтобы определить хорошие совпадения.

```python
for i, (m, n) in enumerate(matches):
    if m.distance < 0.7 * n.distance:
        matchesMask[i] = [1, 0]
```

Теперь визуализируем совпадения.

```python
draw_params = dict(
    matchColor=(0, 255, 0),
    singlePointColor=(255, 0, 0),
    matchesMask=matchesMask,
    flags=cv2.DrawMatchesFlags_DEFAULT,
)

img3 = cv2.drawMatchesKnn(img1, kp1, img2, kp2, matches, None, **draw_params)
```

## Local Feature Matching with Transformers (LoFTR)

LoFTR был предложен в [LoFTR: Detector-Free Local Feature Matching with Transformers](https://arxiv.org/pdf/2104.00680.pdf) авторами Sun et al.
Вместо детекторов признаков LoFTR использует подход к сопоставлению признаков на основе обучения.

Давайте оставим это простым и снова используем пример с пазлом. Вместо того чтобы просто сравнивать изображения пиксель за пикселем, LoFTR ищет конкретные ключевые точки, или признаки, на каждом изображении. Это как идентифицировать углы и края каждого кусочка пазла. И как кто-то, кто очень хорошо собирает пазлы, может фокусироваться на отличительных метках, LoFTR идентифицирует эти уникальные точки на одном изображении. Это могут быть ключевые ориентиры или структуры, которые выделяются. Как мы уже узнали, важно, чтобы алгоритм сопоставления обрабатывал изменения поворота или масштаба. Если признак повёрнут или изменён в размере, LoFTR всё равно его распознает. Это как собирать пазлы, где кусочки могут быть перевёрнуты или подстроены. Когда LoFTR сопоставляет признаки, он назначает оценку сходства, чтобы указать, насколько хорошо признаки выравниваются. Более высокие оценки означают лучшие совпадения. Это как ставить оценку тому, насколько хорошо один кусочек пазла подходит к другому.
LoFTR также инвариантен к определённым преобразованиям: он может справляться с вариациями освещения, угла или перспективы. Это критично при работе с изображениями, которые могли быть сняты в разных условиях. Способность LoFTR устойчиво сопоставлять признаки делает его ценным для задач вроде сшивки изображений, где вы бесшовно объединяете несколько изображений, идентифицируя и соединяя общие признаки.

Мы можем использовать [Kornia](https://github.com/kornia/kornia), чтобы найти совпадающие признаки на двух изображениях с помощью LoFTR.

Импортируйте необходимые библиотеки.

```python
import cv2
import kornia as K
import kornia.feature as KF
import matplotlib.pyplot as plt
import numpy as np
import torch
from kornia_moons.viz import draw_LAF_matches
```

Загрузите и измените размер изображений.

```python
from kornia.feature import LoFTR

img1 = K.io.load_image(image1.jpg, K.io.ImageLoadType.RGB32)[None, ...]
img2 = K.io.load_image(image2.jpg, K.io.ImageLoadType.RGB32)[None, ...]

img1 = K.geometry.resize(img1, (512, 512), antialias=True)
img2 = K.geometry.resize(img2, (512, 512), antialias=True)
```

Укажите, является ли изображение «indoor» или «outdoor».

```python
matcher = LoFTR(pretrained="outdoor")
```

LoFTR работает только с изображениями в градациях серого, поэтому преобразуйте изображения в градации серого.

```python
input_dict = {
    "image0": K.color.rgb_to_grayscale(img1),
    "image1": K.color.rgb_to_grayscale(img2),
}
```

Выполним инференс.

```python
with torch.inference_mode():
    correspondences = matcher(input_dict)
```

Очистите соответствия с помощью Random Sample Consensus ([RANSAC](https://en.wikipedia.org/wiki/Random_sample_consensus)). Это помогает справляться с шумом или выбросами в данных.

```python
mkpts0 = correspondences["keypoints0"].cpu().numpy()
mkpts1 = correspondences["keypoints1"].cpu().numpy()
Fm, inliers = cv2.findFundamentalMat(mkpts0, mkpts1, cv2.USAC_MAGSAC, 0.5, 0.999, 100000)
inliers = inliers > 0
```

Наконец, мы можем визуализировать совпадения.

```python
draw_LAF_matches(
    KF.laf_from_center_scale_ori(
        torch.from_numpy(mkpts0).view(1, -1, 2),
        torch.ones(mkpts0.shape[0]).view(1, -1, 1, 1),
        torch.ones(mkpts0.shape[0]).view(1, -1, 1),
    ),
    KF.laf_from_center_scale_ori(
        torch.from_numpy(mkpts1).view(1, -1, 2),
        torch.ones(mkpts1.shape[0]).view(1, -1, 1, 1),
        torch.ones(mkpts1.shape[0]).view(1, -1, 1),
    ),
    torch.arange(mkpts0.shape[0]).view(-1, 1).repeat(1, 2),
    K.tensor_to_image(img1),
    K.tensor_to_image(img2),
    inliers,
    draw_dict={
        "inlier_color": (0.1, 1, 0.1, 0.5),
        "tentative_color": None,
        "feature_color": (0.2, 0.2, 1, 0.5),
        "vertical": False,
    },
)
```

Лучшие совпадения визуализированы зелёным, а менее уверенные — синим.
